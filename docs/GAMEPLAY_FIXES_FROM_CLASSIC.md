# Gameplay Fixes From Classic

This document tracks parity issues where the comparison against the
`e761b745d91983f4ba9803b670bae5208dbb8717` classic baseline exposed either
gameplay bugs or parity scaffolding problems. The `Classification` column
distinguishes visible gameplay changes from recorder, harness, golden, and
safety-only fixes.

`wip/parity-with-classic` means the modern gameplay branch was changed to match
classic behavior. `parity-companion` means the classic companion recorder was
changed because the e761 behavior was judged to be a bug that should not be
preserved.

Every parity golden is a capture from the old game (branch `parity-companion`,
the classic recorder) at the commit `tests/parity/golden/DRIFT_LEDGER.md` pins,
and no golden is captured from the current game. From 2026-10-04 every
deliberate departure that a parity row reaches is also ported into the old
game, and #349 (2026-10-05) ported the ones whose goldens were still
current-game captures, so the ledger's "Open" list is empty. A row whose "Side
fixed" names this branch only either brought this branch back to classic
behaviour (its golden stays an old-game capture) or is a departure the old game
does not carry. Such a departure is golden-neutral, because no parity row
reaches it (the full capture at the ledger's pin `cmp`s equal to every golden
without it); the first parity row that does reach it must port it first.
