# Gameplay Fixes From Classic

This document tracks parity issues where the comparison against the
`e761b745d91983f4ba9803b670bae5208dbb8717` classic baseline exposed either
gameplay bugs or parity scaffolding problems. The `Classification` column
distinguishes visible gameplay changes from recorder, harness, golden, and
safety-only fixes.

`wip/parity-with-classic` means the modern gameplay branch was changed to match
classic behavior. `parity-companion` means the classic companion recorder was
changed because the e761 behavior was judged to be a bug that should not be
preserved.

| Issue | Classification | Side fixed | Effect | Why that side was fixed |
|---|---|---|---|---|
| Recorder baseline included post-e761 OpenGlad history | Scaffolding | `parity-companion` | The companion branch was rebuilt from raw `e761b745d91983f4ba9803b670bae5208dbb8717` and reimplemented only the parity recorder/dumper support on top of it. | Golden recordings must represent the chosen classic baseline plus instrumentation. Keeping normal OpenGlad development after e761 in the companion branch made the baseline inauthentic. |
| Golden recordings from the wrong baseline | Scaffolding | Golden recordings on `wip/parity-with-classic` | Golden JSON recordings were regenerated from the rebuilt e761 companion recorder. | The branch should compare against authentic e761 behavior, not recordings produced from a later post-e761 companion history. |
| Parity runner event/RNG drift | Scaffolding | `wip/parity-with-classic` | The runner was aligned to classic RNG observation, event capture, metadata normalization, score event handling, positional-sound visibility, and screen-completion behavior. | These were harness differences, not gameplay differences. The modern parity runner needed to replay and compare the same observable stream that the e761 recorder emits. |
| Empty scenario completion stream | Scaffolding | `wip/parity-with-classic` | Empty scenarios now keep classic completion events such as `set_end` and `end_game` instead of filtering them out. | The harness was dropping real classic events. The e761 recorder was correct to include the completion stream. |
| Small slime no-ranged flag | Visible gameplay | `parity-companion` | Small slimes could incorrectly fire free blob projectiles at range. They should still be able to melee, but should not launch ranged blobs. | e761 had a loader typo: it compared `order` to `FAMILY_SMALL_SLIME` instead of comparing `family`. The surrounding setup and modern descriptor both clearly intended `BIT_NO_RANGED` for small slimes. |
| Giant skeleton bloodspot | Visible gameplay | `parity-companion` | Giant skeletons left a bloodspot/death stain when dying. They should behave like the other undead/no-bloodspot enemies. | e761 omitted `FAMILY_GIANT_SKELETON` from the same no-stain death class as skeleton/ghost/tower. The modern descriptor already had `leaves_bloodspot = false`, which matches the intended undead behavior. |
| Expired poison cloud still acting | Visible gameplay | `parity-companion` | A cloud whose lifetime had expired could still attack and schedule movement during the same tick it died. | Dead effects continuing to act is a classic bug. The correct behavior is to return immediately after marking the cloud dead and running `death()`. |
| Poison cloud random-walk underflow | Visible gameplay | `parity-companion` | Poison cloud drift was biased because `random(3) - 1` underflowed when `random(3)` returned zero. Negative directions collapsed or became implementation-dependent before the walk command was queued. | The intended random walk is `-1`, `0`, or `1` per axis, excluding `0,0`. Casting to signed before subtracting restores the obvious intended behavior. |
| Generator spawn direction underflow | Visible gameplay | `parity-companion` | Generator firing/spawn direction could corrupt the intended `-1`, `0`, or `1` random direction when unsigned subtraction underflowed. | The generator path intended signed direction choices. Casting to signed before subtracting avoids implementation-dependent large values. |
| Slime/weapon auto-attack false positive | Visible gameplay | `parity-companion` | Ordinary projectiles could trigger `living::collide()` as if they were attackable targets. In the slime case, a soldier's thrown knife (`ORDER_WEAPON`, `FAMILY_KNIFE == 0`) falsely matched generator `FAMILY_TENT == 0`, causing the slime to start an attack response to the projectile itself. | e761 compared raw family IDs without considering object order. Family IDs are reused across orders, so the predicate must be order-aware: living and generators are attackable, while only explicitly attackable weapon objects such as glow, tree, and door should be auto-attackable. |
| Ghost animation sentinel/OOB access | Safety/scaffolding | `parity-companion` | Ghost animation could read the `-1` sentinel or adjacent memory after the animation cycle moved past the valid sequence. | This was unsafe memory/sentinel behavior, not intended gameplay. The companion was changed to complete the animation when `cycle >= sequence_length`. |
| Fire elemental animation sentinel/OOB access | Safety/scaffolding | `parity-companion` | Fire elemental animation had the same stale-cycle sentinel/OOB behavior as ghost animation. | Same root cause as the ghost case: classic was reading beyond the valid animation sequence, so the companion was bounded instead of preserving undefined behavior. |
| Druid faerie summon level | Visible gameplay | `wip/parity-with-classic` | Druid-summoned faeries inherited the druid's level in the modern branch, changing their stats and combat strength. | e761 did not copy the summoner's level for this summon path. The modern helper introduced extra state, so the branch was changed to create the faerie and set only the classic fields. |
| AI `direct_walk()` fire check | Visible gameplay | `wip/parity-with-classic` | Ranged AI could walk instead of shooting, or shoot only after different turning, because the branch normalized the target vector before checking whether it could fire. | e761 passes the raw target vector into `fire_check()`, preserving slope information for facing/aiming. Normalized deltas are appropriate for movement steps, not for the fire-vs-walk decision. |
| Facing/turn parity | Visible gameplay | `wip/parity-with-classic` | Actors could rotate along a different path, affecting facing frames, `lastx`/`lasty`, attack direction, and firing timing. | The branch defensively clamped invalid/transient directions to `FACE_UP`. Classic uses the raw direction value in its modulo turn arithmetic, so the clamp changed behavior. |
| Positional death sounds | Visible gameplay | `wip/parity-with-classic` | Death sounds could play when classic would consider the death off-screen or otherwise not audible through positional sound visibility. | e761 gates positional death sounds by visibility. The branch emitted too broadly, so the branch sound path was restricted to classic visibility rules. |
| Combat score/XP timing | Visible gameplay | `wip/parity-with-classic` | Score and XP changes could occur at different ticks or be attributed differently from classic combat. | Modern combat refactoring moved reward sequencing away from classic behavior. The branch was changed so hit rewards, owner/weapon attribution, and melee/ranged scoring occur in the classic locations. |
| Generator spawn double `set_difficulty` (A12b) | Visible gameplay | This branch (goldens regenerated) | Every generator-emitted living received `set_difficulty` twice — once in `create_weapon()` at the GENERATOR's level, then again in `fire()`'s generator branch at the rolled level — compounding two additive hp/mp/regen boosts and squaring the difficulty multiplier (genL=5, rolled L3, base 10 hp: 384 vs the intended 109; 6x on Hard). The `create_weapon()` call was removed; spawns now match a fresh living given one rolled-level application. | Classic (2002) did exactly the same double application, so it was baked into the goldens — but it is unambiguously a bug (the rolled level is the spawn's real level; the first application is overwritten conceptually but its side effects accumulate). Regenerated goldens: `generator_tent_emission_scen99`, `generator_tower_emission_scen99`, `generator_treehouse_emission_scen99`, `effect_marker_emission_scen99`, `generator_saturation_scen99` (the last two also carry the teleport-probe change below). Predicate pins updated in `scenario_table.h` alongside. |
| Teleport destination probe eats treasures / obeys transient flight (A6/A7) | Visible gameplay | This branch (goldens regenerated) | `walker::teleport`/`teleport_ranged` probed destinations via `query_passable`, whose obmap half EATS treasures at rejected spots and whose grid half accepts trees/boulders under transient `flight_left`; teleports are now probed eat-free under ground rules and are floor-aware on multi-floor levels. | A rejected teleport must not consume items the caster never touched, and a blink must not park a caster permanently inside scenery. Changes teleport RNG acceptance, so the mage-emission goldens above (`effect_marker_emission_scen99`, `generator_saturation_scen99`) shifted cadence together with A12b. |
| SAVE_ALL mission-loss scoping (F2) | Visible gameplay | This branch (zero golden regens — no parity scenario sets `SCEN_TYPE_SAVE_ALL`) | Classic fails a SAVE_ALL mission when ANY named team-0 living dies — including archmage illusions (named "Phantom"), cleric raises, and charmed foes temporarily wearing team 0, so expiring ammunition could end the mission. Now: (a) summoned walkers (`walker::summoned()`, set at every conjure site) and charmed foes (`real_team_num != 255`, legacy branch only) never trip the check; (b) a per-placed-NPC "protected" flag (level-file v10 `npc_flags` bit 2) scopes the watch — when any placed NPC carries it, ONLY flagged walkers are mission-critical; with none present the legacy any-named-team-0 rule applies unchanged (full back-compat: no stock campaign sets bit 2). | The classic rule made summons literal loss conditions and every named ally a mission-fail tripwire (the Westlands L4/L10/L12/L24 named-ally pathology). Summons are ammunition, not characters; the flag lets a campaign author say exactly whose death ends the mission (Westlands: the Bearer alone, on all 16 SAVE_ALL levels). Parity is untouched by construction: every new branch is gated on flags no golden scenario sets. |
| Guard-standoff melee deadlock (F1) | Visible gameplay | This branch (goldens audited/regenerated as needed) | Three cooperating deterministic rules, no new RNG sources. (1) `fire_check()` gained an optional denial out-param (its reach gate now runs before the NO_RANGED/magic gates so those denials imply "foe in reach"; same returns, same RNG draws for all callers). COMMAND_ATTACK keys off it: a shot denied only by orientation — `Facing`, or `NoRanged` at bump range — now snap-faces the foe (`walker::face_delta`: curdir+enddir+lastx/lasty in one act) instead of walking. (2) obmap interpenetration escape: two livings left overlapped by a transient pass-through were in an ABSORBING trap (every exit step still "collided" with the body around the mover), forming unkillable shield pairs; strictly separating moves now pass. (3) Coincident clinch breaker: a foe at exactly our position collapses the COMMAND_ATTACK approach delta to (0,0), which classic answered with `walkstep(0,0)` — a frozen no-op; the walker now steps along its facing. | Classic answered EVERY denied `fire_check` with "walk toward the foe"; the foe's own body blocked that step, `walkstep`'s blocked-NPC fallback set curdir PERPENDICULAR (the wall-slide), and the re-collapsed approach delta face-danced two adjacent fighters forever without one landed swing (Westlands Wave E: L25's eternal last foe vs a full-health crew; L2's companies parked mid-road). Melee-only families (orcs — most Westlands enemies) had the same wedge on their bump path, and the pass-through traps upgraded wedges into permanent unkillable pairs. Regression pins: `tests/unit/test_melee_standoff.cpp` (facing-snap primitive is red pre-fix; Westlands L2 crew now fights past mid-road, sweeps the road, and keeps 4/4 alive on 3 pinned seeds — pre-fix: one crew wipe and two one-man losses with the bend-1 picket standing). Audited golden regens (16): `family_ghost`/`family_small_slime`/`special_slime_1` (NO_RANGED families duel engaged at bump range instead of orbit-wandering; ghost repinned to the engaged-duel endpoint), `smoke_nonempty` (the closing orc holds facing at reach — first exchange slides past the 60-tick horizon, tracks empty), `multiplayer_two_teams` (melee resolves along the snap-faced path; archer hp pin 78->90), `special_druid_2`/`invulnerable_potion`/`consumable_inventory_state`/`treasure_drumstick_pickup`/`treasure_stain_pickup` (1-13 tick cadence shifts in otherwise identical fights), the five `event_*_emission` arenas (the enemy soldier used to charge down the player's knife lane eating scoring hits; the line now leads with the orc and the player aims east via a per-arena input script so the ScoreChange canary keeps teeth), and `effect_protection_emit` (the "idling" friendly was actually trapped inside the druid by the classic interpenetration bug; respawned at a legal separation that keeps it in cast range). |
| Multi-floor pathing wedges (Westlands L24 "baddies unable to path in the mountain") | Visible gameplay | This branch (zero golden regens — all four fixes are `floor_count() > 1` gated, and og_test_parity's 187 goldens are single-floor) | Four cooperating deterministic rules, no new RNG sources, all gated on multi-floor levels. (1) A* no-corner-cut: the pathing graph emitted diagonal cell transitions past blocked flanking cells, which a full-cell body can NEVER take (its swept box overlaps the flank at every pixel offset) — in an X-pinch (L24's lava + scree-boulder pockets) the follower seized on the impossible edge forever. Diagonal expansion now requires both orthogonal flanks open (grid-passable, plus the non-flyer air skip). (2) Follow-path alignment assist: a path node counts as reached while the body still spills up to 15px into the next row/column; a cardinal hop hugging an impassable cell on the spill side stayed pixel-blocked at every misaligned offset while walkstep's fixed fallback marched the walker back OUT of alignment — a deterministic 2-tick oscillation (the L24 tower-terrace mage wedge). The follower now slides toward exact alignment (per-pixel, collision-checked, RNG-free) when that exact shape occurs. (3) Flyer cross-floor bypass: flyers never change floors (no stair edges in the graph, `apply_z_motion` skips them), so a cross-floor foe is unreachable BY DESIGN — yet `walk_to_foe` force-ran a full-map A* exhaustion every tick and `path_toward_stair` parked the flyer ON a stair it could never take (the caldera-ghost wedge). Flyers now keep the classic floor-blind 2D chase (shadow the foe from their own floor). (4) Floor-keyed `find_near_foe`: the spiral probe called `obmap_get_list(x, y)` whose floor parameter DEFAULTS TO 0, so upper-floor walkers were blind to foes beside them and latched ground-floor foes under their 2D position; the probe now passes the searcher's floor (cross-floor acquisition intentionally remains via `find_far_foe`). | Headless sweeps of Westlands L24 (5 seeds x 4000 ticks) showed ~5 permanently wedged hostiles per run in three clusters (tower mages oscillating ±2px for 3000+ ticks, caldera ghosts pinned on the summit stair, X-pinch seizures on the terrace); after the fixes the only long-stationary hostiles are flyers hovering at an unreachable foe's 2D shadow — engaged, transient, by design. Single-floor behavior is byte-identical by construction: an UNGATED alignment assist was tried and moved first-hit timing in 18 single-floor family-duel goldens (branch tick 212 vs master 484 for `family_soldier_scen99`) and would have shifted calibrated campaign balance, so single-floor levels deliberately KEEP the classic wedge shapes. Regression pins: `tests/unit/test_zaxis.cpp` (`flyer_with_cross_floor_foe_shadows_it_and_never_parks_on_stair`, `multifloor_astar_never_emits_diagonals_past_blocked_flanks`, `misaligned_walker_aligns_and_turns_a_one_lane_corner`, `find_near_foe_probes_the_searchers_floor`). Long Season multi-floor scen11 recalibrated 6 -> 5 (`tests/unit/test_longseason_calibration.cpp`); Westlands survival floors unchanged. |
| Single-floor pathing wedges (Westlands L2 "The Forest Road" — orcs walking into walls, wedged columns, wall-facing statues) | Visible gameplay | This branch (22 goldens audited/regenerated) | Four cooperating deterministic rules, no new RNG sources, none gated. (1+2) The L24 wave's A* no-corner-cut and follow-path alignment assist lose their `floor_count() > 1` gates: single-floor corridor mazes exhibit the exact defect classes the gates were preserving (corner-cut edges a full-cell body can never take; the deterministic 2-tick misalignment dance at convex corners), so both rules now run on every level. (3) Shove command-theft probe: `living::shove` cleared a friendly target's command queue and injected a COMMAND_WALK even when that walk was terrain-blocked; a shover re-colliding every tick refilled the untakeable walk forever, so the target's own COMMAND_SEARCH never ran again — three interlocked bodies froze 350+ ticks on L2's one-cell grass strips (the s1337 GDB capture). The shove now probes the injected walk's baby step against the GRID only (no obmap — ally-chain scooting intact, no treasure-eat side effects) after the unchanged rng(3) roll, and leaves the queue alone when the inject provably cannot move the target. (4) Guard facing gate: `act_guard` faced whatever `find_near_foe` returned — which has no range or sight limit — so guards posted beside tree bands pivoted nose-into-trees at cross-wall foes (14% of L2 guard film ticks). Only the facing turn is gated now, on family sight range plus a clear straight-line cell ray (`GameWorld::clear_sight_line`, opaque = tree crowns/trunks + wall faces, i.e. tiles an unowned projectile can never pass; water/boulders stay transparent so island archers keep engaging); foe acquisition, COMMAND_FIRE attempts, and every RNG draw are unchanged. | The Westlands L2 RCA classified every stuck/oscillating hostile on the preview card into these classes; the L24 fixes deliberately excluded single-floor levels to protect the parity goldens, so L2 exhibited exactly the gated defects. Bisection attribution: the corner-cut prune moves 18 goldens (`family_soldier`/`elf`/`archer`/`mage`/`skeleton`/`cleric`/`fireelemental`/`slime`/`small_slime`/`medium_slime`/`thief`/`druid`/`big_orc`/`barbarian`/`archmage`/`golem` `_scen99` + `special_archmage_scen123` + `effect_chain_scen9410` — first-hit timing drops as duels engage instead of corner-dancing, e.g. `family_soldier` first HIT tick 484 -> 198, `family_medium_slime` finally REACHES the player), the alignment assist moves 4 more (`family_orc_scen99`, `weapon_boulder_emission_scen99`, `effect_explosion_emission_scen99`, `effect_heartburst_multitarget_scen99` — crowd approach paths shift; a transient FAMILY_HIT effect leaves the final weapon_boulder tick), and the shove probe + facing gate move ZERO goldens (verified: dumps byte-identical with only fixes 3+4 applied). Every regenerated golden audited: fights engage/resolve rather than wedge/jitter; no scenario lost a walker or an event class it previously had (the one removed dump entry is the transient HIT). Six `WalkerPositionMoved` pins repinned to the engaged endpoints with dated comments. Regression pins: `tests/unit/test_forest_pathing.cpp` (all four classes red under classic behavior, green post-fix, including the reconstructed 3-body column livelock).
