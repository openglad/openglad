## New Outputs
- 21 new `ScenarioSpec` entries in `kScenarios`, one per family
  `FAMILY_SOLDIER..FAMILY_TOWER1`. Naming:
  `family_<symbolic_lowercase>_scen99` or `_scen9301`. Each spec uses:
  - `tick_budget = 150`.
  - `fresh_arena = true` so the runner clears pre-existing walkers via
    `scenario_runtime::clear_world_entities(world)` between `level.load()`
    and `apply_post_load_spawns(world, spec)`.
  - `spawns[]`: target family on team 0 at `(120, 120)` and
    `FAMILY_SOLDIER` on team 1 at `(180, 120)` as a sparring partner;
    generators get an additional spawn entry of the corresponding
    generator family.
  - `inputs[]`: `{ {5, 0, K_FIRE}, {64, 0, K_NONE} }` so the target
    attacks at tick 5 and stops at tick 64. Non-combatant generators
    have empty `inputs`.
  - `exercises`: appropriate bit flag from Phase 03's `Exercises` enum.
- Mirror entries in `../openglad-master/tools/parity_scenario_table.h`
  (byte-for-byte synchronised), committed on `parity-companion`.
- 21 golden files in `tests/parity/golden/family_*.json` captured in
  this phase by the rebuilt master companion via
  `scripts/parity/capture_master_golden.sh tests/parity/golden/`
  filtered to the new ids; schema-validated; committed. Canonical
  goldens — not regenerated by any later phase except Phase 07's audit.
- `.plan/parity-coverage-manifest.md` updated with
  `covering_scenario_id` populated for all 21 walker families.

## Implementation Details
- `fresh_arena = true` is required so families that depend on RNG
  consumption during `load()` do not accumulate pre-existing walkers
  before the per-family probe.
- Family-specific gotchas:
  - `FAMILY_SLIME` / `FAMILY_SMALL_SLIME` / `FAMILY_MEDIUM_SLIME`: on
    death, slime splits; the dump captures split products.
  - `FAMILY_GHOST`: ghost-scare effect (`FAMILY_GHOST_SCARE`) fires on
    enemy contact — also covers an effect family.
  - `FAMILY_TOWER1` is a static turret; will not move but fires
    weapons.
- Capture sequence:
  1. Confirm `../openglad-master/build/ci-test/parity_dump_master` is
     the binary built from the SHA recorded in the manifest frontmatter.
  2. `scripts/parity/capture_master_golden.sh tests/parity/golden/`
     filtered to the 21 new ids.
  3. `python3 scripts/parity/validate_schema.py tests/parity/golden/family_*.json`.

## Verification Phases
- **Phase ID**: `04a-check-family-coverage`
  - **Type**: `check`
  - **Bounce Target**: `04-walker-family-scenarios`
  - **Purpose**: Confirm every entry in `kRequiredWalkerFamilies[]` is
    observed in the union of `dump.walkers[*].family` and that 21 family
    golden files exist on disk.
  - **Commands**:
    ```
    cmake --build --preset ci-test --target og_test_parity
    ./build/ci-test/og_test_parity \
        --gtest_filter='Parity.coverage_gate_walker_families'   # exits 0
    [ "$(ls tests/parity/golden/family_*.json | wc -l)" -eq 21 ]
    ```

- **Phase ID**: `04b-check-byte-equal-vs-master`
  - **Type**: `check`
  - **Bounce Target**: `04-walker-family-scenarios`
  - **Purpose**: For each family scenario, re-derive evidence by
    running the rebuilt master companion and `diff -q` against the
    committed branch golden. Any divergence flags either a regression
    (Phase 07 will classify) or an out-of-date golden.
  - **Commands**:
    ```
    (cd ../openglad-master && cmake --build --preset ci-test \
        --target parity_dump_master)
    for id in $(ls tests/parity/golden/family_*.json \
                  | xargs -n1 basename | sed 's/\.json$//'); do
      ../openglad-master/build/ci-test/parity_dump_master \
          --scenario "$id" --out "/tmp/${id}.json"
      diff -q "tests/parity/golden/${id}.json" "/tmp/${id}.json"
    done
    ./build/ci-test/og_test_parity --gtest_filter='Parity.family_*'  # 21 passes
    ```
    All `diff -q` invocations and the test run must exit 0.
