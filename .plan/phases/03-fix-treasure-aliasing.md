## New Outputs
- **Per-Order family resolution in `state_dump.cpp`.** Today (`tests/parity/state_dump.cpp:98-130`) a single `family_symbol(int32_t)` is backed by one Living-order table and called by `collect_walkers` (`:168`), `collect_effects` (`:193`), and `collect_weapons` (`:218`). Phase 03:
  - Introduces free function `family_symbol_by_order(int32_t order, int32_t family_id)` in `state_dump.cpp`, backed by 5 small static `std::string_view` tables — one per `Order::Living`, `Order::Weapon`, `Order::Treasure`, `Order::Generator`, `Order::Effect`.
  - Rewrites `collect_walkers`, `collect_weapons`, `collect_effects` to call `family_symbol_by_order(static_cast<int32_t>(w->query_order()), static_cast<int32_t>(w->family()))`.
  - **Deletes** the legacy `family_symbol` free function outright (no thin-wrapper). Any other call site is migrated to `family_symbol_by_order(...)` in the same commit.
  - Same change mirrored byte-for-byte to `../openglad-master/tools/parity_dump_state.cpp`.
- **New `FactKind::TreasureFamilyOfOrderRemovedFromOblist`** appended at the end of the enum. Factory signature: `TreasureFamilyOfOrderRemovedFromOblist(int32_t family, int32_t order, std::string label)`. Evaluator walks `dump.walkers[]` and compares each entry's `family` string against the table-resolved symbol for `(family, order)` — predicate satisfied iff no remaining walker matches. Existing `TreasureFamilyRemovedFromOblist(family, label)` factory left intact.
- **Updated `tests/parity/scenario_table.h`**: every `treasure_*_pickup_scen99` row's `TreasureFamilyRemovedFromOblist(arg0)` replaced by `TreasureFamilyOfOrderRemovedFromOblist(arg0, kOrderTreasure)`. `kInputsTreasurePickup` and spawn lists unchanged.
- **Updated `tests/parity/test_parity_coverage_gate.cpp`**: BOTH `behavioural_coverage_gate_treasures` (cpp:323-334) AND the umbrella `behavioural_coverage_gate`'s treasure-family branch (cpp:421-424 — the `append_family("treasure_family", ..., FactKind::TreasureFamilyRemovedFromOblist)` call) accept either `TreasureFamilyRemovedFromOblist` (legacy) OR `TreasureFamilyOfOrderRemovedFromOblist` (new) when computing the bound-family set, so previously-aliased families (STAIN=0, EXIT=8) can bind via the new factory. Introduces free helper `any_treasure_binding(int32_t family_id)` returning true iff any predicate of either kind binds `arg0 == family_id` (with `arg1 == kOrderTreasure` for the new kind). Both gate sites use this helper. The `missing_family_bindings(..., FactKind::TreasureFamilyRemovedFromOblist)` call at cpp:327-330 is replaced with an equivalent loop using `any_treasure_binding`.
- `tests/parity/scenario_facts_generated.json` regenerated by the existing tool.
- Mirror updates: `../openglad-master/tools/parity_scenario_table.h`, `tools/parity_dump_state.{cpp,h}` (legacy `family_symbol` deleted on companion side too).
- New goldens for every treasure row: `tests/parity/golden/treasure_*_pickup_scen99.json` (12 files), captured via `scripts/parity/capture_master_golden.sh <id>` against the resynced + patched companion. Script's existing single-scenario invocation; `--all` is not introduced until Phase 04.
- Existing goldens regenerated where the new dumper would produce a different `walkers[].family` string. Enumeration loop:
  ```
  mkdir -p /tmp/p03-staging
  for g in tests/parity/golden/*.json; do

      ../openglad-master/build/ci-test/parity_dump_master "$id" > "/tmp/p03-staging/$id.json"
      if ! diff -q "$g" "/tmp/p03-staging/$id.json" > /dev/null; then
          cp "/tmp/p03-staging/$id.json" "$g"
      fi
  done
  ```
- `.plan/parity-harness-design.md` appended with a short section documenting the new FactKind and the per-Order resolution rule.

## Implementation Details
- The dump JSON schema is unchanged — only the string content of `walkers[].family` changes for non-Living oblist entries.
- The new enum value is appended (not inserted) so existing serialised `FactKind` ordinals never shift.
- `scenario_facts_generated.json` is regenerated by `scripts/parity/scenario_facts_dump_main` (or the existing tooling that produces this file). Implementation runs that tool, not hand-edits the JSON.
- Companion `parity_dump_master` must be rebuilt after `parity_dump_state.cpp`/`h` and `parity_scenario_table.h` are updated.
